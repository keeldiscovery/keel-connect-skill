# Implementation Plan: One source, four trees, one build

**Branch**: `004-skill-packaging` | **Date**: 2026-09-09 | **Spec**: [spec.md](spec.md)

**Design of record**: keel-cloud `canon/designs/keel-skill-design.md`, §13 step 4.

## Summary

`make dist` is thirty lines of `cp` around two `sed` substitutions, and that is the whole point:
the build is boring so the test can be strict. Everything interesting in this spec is in
`tests/test_dist.py`, which is the gate the design asks for -- it asserts that four directories
are the same bytes, that every manifest names one version, that no manifest carries behaviour, and
that the one file every host reads has not grown a field, a URL, an ecosystem or a host name.

## Technical Context

**Language/Version**: GNU/BSD `make` and POSIX `sh` for the build; Python 3.9+ stdlib for the
catalogue-entry generator and for L1. `install.sh` and `test-install.sh` are bash 3.2 compatible,
because macOS ships bash 3.2 and a founder is the one running them.

**Primary Dependencies**: none. No `pyyaml`, no packaging library, no template engine -- the CI
matrix installs nothing (R-2), so the build must work with nothing installed.

**Storage**: `dist/`, gitignored, rebuilt from scratch by every `make dist`.

**Testing**: `tests/test_dist.py` builds once in `setUpModule` and reads what it wrote. 50 cases.
`claude plugin validate --strict` runs when the CLI is present.

**Target Platform**: the build runs where a release is built -- Linux and macOS. Windows rows skip
L1 with a message when there is no `make`.

**Performance Goals**: `make dist` is under a second on the founder's machine.

**Constraints**: copy, never transform; one substitution token (`${VERSION}`) and no other; no
network at build time.

## Decisions this plan made, that the design left open

**`SKILL.md` ships in the Spec Kit tree too.** §8.4's listing of `dist/speckit/` does not name it,
but §10.1's L1 says all **four** trees carry byte-identical `SKILL.md`, and §8.1's table calls
`commands/` the extension's *extra* file rather than its replacement. The four-tree assertion is
the one that has teeth, so it wins: the extension carries the same `SKILL.md` at its root, where a
host that reads agentskills.io directories will find it and where the two command files point
readers. It costs one file and closes the one gap through which the extension could have drifted.

**`LICENSE` in every tree.** The design names it in the plugin and the Spec Kit tree. It is placed
in the bare tree and the Copilot drop as well, and in the marketplace tree: every one of them is a
directory somebody copies into their own repository, and a copy of Apache-2.0 code without its
licence is a thing to fix later at somebody else's cost. Not a design change -- a gap filled the
way the design fills the other two.

**`dist/marketplace/` is a tree, not a repository.** `make dist` writes
`.claude-plugin/marketplace.json` and a `README.md` saying the directory is generated and where to
edit it. Creating `keeldiscovery/keel-marketplace`, pushing, and cutting the `release` branch are
the founder's acts; a build step that created repositories would be a build step nobody could run
twice.

**The catalogue entry is generated by a small reader, not by `pyyaml`.** `packaging/catalog_entry.py`
reads the manifest **we** generated from **our own** template, in a fixed shape, and fails loudly
rather than guessing. A regex reader against a stranger's YAML would be wrong; against a file this
repository writes two lines earlier it is honest, and it keeps the zero-dependency posture the
matrix depends on.

**L1 runs the validator that exists and names the one that does not.** `claude plugin validate
--strict` is real and is used, on the plugin and on the marketplace. `specify extension validate`
is not a command on the CLI installed here (0.16.4), so the Spec Kit manifest is checked
structurally against §8.4's fields, and `SpecKitManifestTestCase`'s docstring records exactly what
was measured, when, and what happened when the built tree was actually offered to `specify`. A test
that implied a validator ran when none did would be worse than no test.

**Where the version substitution happens.** In `make dist`, with `sed`, on two template files whose
names end `.in`. `packaging/` holds no substituted file and `dist/` holds no template, so it is
never ambiguous which of the two you are looking at.

## Constitution Check

- **One skill, one repository.** L1's first four assertions are exactly this, and they compare
  bytes rather than trusting the recipe.
- **No behaviour in a manifest.** Asserted in both manifests, by forbidden-key list.
- **Nothing published by a build step.** `make dist` writes a directory. Every act with a
  consequence outside this machine -- a push, a branch, a release, an issue -- stays the founder's.
- **No ecosystem in the skill.** The ecosystems live in `packaging/`, and L1 greps the skill and
  the scripts to prove none of them leaked in.

## Complexity Tracking

None. The one thing that could have grown complicated -- keeping four copies honest -- is answered
by not having four copies.
