# Implementation Plan: The runtime travels inside the skill

**Branch**: `003-bundled-runtime` | **Date**: 2026-09-08 | **Spec**: [spec.md](spec.md)

**Design of record**: keel-cloud `canon/designs/keel-skill-design.md`, §13 step 3.

## Summary

Four moving parts, in dependency order.

1. **A build step.** `make runtime` copies `keel_runtime/` from a sibling keel-runtime checkout and
   stamps `RUNTIME_VERSION`. It refuses a dirty or commit-less checkout, because the stamp has to
   name exactly what was copied. The package is gitignored; the stamp is not.
2. **A resolution module.** `scripts/_runtime_location.py` holds §3.2's three rules once, for both
   this script and the disconnect script that spec `002` will add. It also holds the one deviation
   the 3.9 floor forced, documented beside the measurement that forced it.
3. **A rewritten script.** The version gate first, then resolve, then `status`, then a detached
   `connect` -- with `--host`, `--executor` passthrough, and `environment` on every shape.
4. **The words.** The output contract rewritten in place for seven shapes; `SKILL.md`'s seven
   replies, the Python clause and one host line; `README.md` and `AGENTS.md` brought level.

## Technical Context

**Language/Version**: Python 3.9+, standard library only. `scripts/keel_connect_check.py` is
additionally constrained to syntax **every** Python 3 parses -- no f-strings, no
`from __future__ import annotations`, no walrus, no variable annotations -- because its version
gate has to run before a `SyntaxError` can happen, and a module is compiled whole before its first
line runs. `_runtime_location.py` is imported after the gate and so is only bound by the 3.9 floor;
it is written to the same rule anyway, since it is one file and one habit.

**Primary Dependencies**: none. `argparse`, `json`, `os`, `shutil`, `subprocess`, `sys`, `time`.

**Storage**: none of this repository's own. The script writes exactly one file -- the launched
`connect`'s log, inside the runtime's home (X-6). Nothing outside it, ever.

**Testing**: `python3 -m unittest discover tests`, 36 cases in one module, against the fake runtimes
in `tests/fixtures/` and -- for the four things a fake cannot prove -- the real bundled runtime's
`status` and `--version`. Green on 3.9 (`/usr/bin/python3`, the founder's floor) and on the newest
interpreter present.

**Target Platform**: macOS/Linux primary (POSIX `start_new_session` for the detached launch);
Windows carried by the matrix's `CREATE_NEW_PROCESS_GROUP` path.

**Performance Goals**: unchanged. `status` is bounded by the runtime's own sub-100ms contract plus
one subprocess spawn; the worst case for a launch is `--wait-seconds` (default 8).

**Constraints**: stdlib only; never block indefinitely; never tie a launched `connect`'s lifetime
to the script's own; never let a malformed `status` escape as an exception; and never let the
script's own file fail to parse on an old interpreter.

## Decisions this plan made, that the design left open

**Where `keel_runtime/` lives, and whether it is committed.** The design is explicit (§3.1, §8.1,
D2): the repository root, gitignored, generated by `make runtime`, with a byte-for-byte comparison
test in spec `004`'s L1. A second committed copy of the runtime's source is precisely the
two-runtimes failure D2 exists to prevent, so it is not committed here. The consequence to be aware
of: **a fresh clone of this repository is not a working skill until `make runtime` has run.** That
is correct -- a founder never receives this repository, they receive a `dist/` tree that
`make dist` (spec `004`) builds with the package in it.

**`RUNTIME_VERSION`'s format.** The design's example is a tag (`v0.2.0`), and keel-runtime has no
tags yet. `make runtime` therefore writes the exact tag when the checkout is on one and
`<__version__>+<short sha>` otherwise -- one line either way, and always something that names a
specific commit. Spec `004` can tighten this to tags-only once one exists.

**Which executor name a detected host asks for.** The design's canonical names are `claude` and
`copilot`, with `claude-code` a permanent accepted alias (C-12). Today's runtime knows only
`claude-code`. Sending an alias that is promised never to be removed is safe; sending a canonical
name the runtime rejects is not. So `claude` -> `claude-code`, and `copilot` -> `copilot`, which
keel-runtime's spec `005` adds and which is recorded in spec.md's Assumptions as the one thing that
does not work yet.

**`cwd`, against §3.2's "cwd is left alone".** Measured 2026-09-08: `python3 -m <pkg>` prepends the
working directory to `sys.path`, ahead of `PYTHONPATH`, so on `/usr/bin/python3` 3.9.6 a caller
whose `cwd` holds an unrelated `keel_runtime/` silently runs *that* one -- the exact failure the
resolution order exists to prevent. `PYTHONSAFEPATH=1` fixes it precisely and is 3.11+, so it is
set *and* the module branch runs with `cwd` set to the directory it resolved. `PYTHONPATH` remains
the mechanism; `cwd` is a shadow guard. Written down in `_runtime_location.py`'s docstring.

**What `SKILL.md`'s frontmatter carries.** Left alone. The design's decision 6 (`name`,
`description`, `license`, and nothing else) and decision 5 (the trigger-first description, which
must also carry disconnect's phrasings) are checked by spec `004`'s L1 and depend on spec `002`'s
script existing. Rewriting the description now to advertise a disconnect that is not built would be
a lie in the one field every host reads.

## Constitution Check

*No formal constitution file exists in this repository. The rules that apply are the design's §9
invariants, cited by id in the spec, in the code and in the tests. The ones this feature could most
easily have broken, and how it does not:*

| Invariant | How this feature satisfies it |
|---|---|
| **D2** one runtime source | `keel_runtime/` is gitignored and written only by `make runtime`, from a checkout that must be clean and on a commit. |
| **X-1** one line of JSON, exit 1 only for `internal_error` | Every shape is printed from `_emit`, and the test harness asserts both halves for *every* case it runs, not only the ones about output. |
| **X-3** the gate parses on any Python 3 | No newer syntax anywhere in that file; a test executes the real file with `sys.version_info` overwritten. |
| **X-4** the override is invisible | `--runtime-path`'s help is `argparse.SUPPRESS`; a test greps the one reachable message for both spellings and for `pip install`. |
| **X-5** no address in the skill | `environment` is relayed from `status` and is `null` when absent; a test drives a runtime that reports none. |
| **D5** no host in a reply | The detection table reads variable *names*; `SKILL.md` carries exactly one host line, marked with a comment saying it is the exception. A test asserts the outcome's key set is unchanged when a host was detected. |
